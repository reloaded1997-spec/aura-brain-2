## TASK 1 — Push Notifications (Phase 3.1)

Implement morning push notifications so users are pulled back into the app when their queue has people due.

### What to build

**Client side:**

1. Create `src/utils/notifications.js`. Export two functions:
   - `requestNotificationPermission(uid)` — calls `Notification.requestPermission()`, then initializes Firebase Messaging via `getMessaging(app)` and `getToken(messaging, { vapidKey: VITE_FCM_VAPID_KEY })`. On success, calls a new `db.js` function `savefcmToken(uid, token)` to persist the token. Returns `{ granted: boolean, token: string | null }`. Gracefully no-ops on browsers that don't support `Notification` (e.g., iOS in non-standalone mode).
   - `removeFcmToken(uid, token)` — calls a new `db.js` function to remove the token from the user doc (used on sign-out).

2. In `src/firebase/db.js`, add:
   - `saveFcmToken(uid, token)` — uses `setDoc` with `merge: true` to push the token into `users/{uid}.fcmTokens` using Firestore's `arrayUnion`. Import `arrayUnion` from `firebase/firestore`.
   - `removeFcmToken(uid, token)` — uses `arrayRemove` to remove a stale token.

3. In `src/context/AuthContext.jsx`, call `requestNotificationPermission(user.uid)` once after a successful sign-in (not on every render — guard with a flag or call only in the sign-in handler). Also call `removeFcmToken` on sign-out before calling `signOut`.

4. In `vite.config.js`, update the `VitePWA` plugin config to include a Firebase Messaging service worker. Add the following to the `workbox` config:
   ```js
   // Allow FCM's own service worker script to be imported
   importScripts: ['https://www.gstatic.com/firebasejs/10.0.0/firebase-app-compat.js',
                   'https://www.gstatic.com/firebasejs/10.0.0/firebase-messaging-compat.js'],
   ```
   And add a `additionalManifestEntries` or `injectManifest` note that the firebase-messaging-sw.js will be served separately. Actually — add a separate `public/firebase-messaging-sw.js` file (described below).

5. Create `public/firebase-messaging-sw.js`. This is the FCM-specific service worker that handles background messages. It must:
   - Import the Firebase compat scripts from CDN
   - Initialize the Firebase app with the same config (read from `src/firebase/config.js` to match — use the same values)
   - Call `firebase.messaging()` and handle `onBackgroundMessage` to show a `self.registration.showNotification(...)` with the notification title/body from the message payload.

   ```js
   // public/firebase-messaging-sw.js
   importScripts('https://www.gstatic.com/firebasejs/10.12.0/firebase-app-compat.js');
   importScripts('https://www.gstatic.com/firebasejs/10.12.0/firebase-messaging-compat.js');

   firebase.initializeApp({
     // paste the config values from src/firebase/config.js here
   });

   const messaging = firebase.messaging();

   messaging.onBackgroundMessage((payload) => {
     const { title, body } = payload.notification;
     self.registration.showNotification(title, {
       body,
       icon: '/icons/icon-192.png',
       badge: '/icons/icon-192.png',
     });
   });
   ```

**Cloud Function (Server side):**

6. In `functions/index.js`, add a new scheduled function `sendDailyQueueNotifications`. It runs every day at 8:00 AM using Firebase's pubsub scheduler:

   ```js
   exports.sendDailyQueueNotifications = functions.pubsub
     .schedule('0 8 * * *')
     .timeZone('America/New_York') // default; per-user timezone is a Phase 5 feature
     .onRun(async (context) => { ... });
   ```

   The function body should:
   a. Query all `users` documents that have at least one entry in `fcmTokens[]`.
   b. For each user, query their `profiles` (where `uid == user.uid`) and `groups` (same). Apply the same load-balancer logic as `queueMath.js` on the server: a profile/group is due if `today - lastClearedDate >= priorityRate`. Use `new Date().toLocaleDateString('en-CA')` for today's date.
   c. Count `totalDue` (profiles + groups due).
   d. If `totalDue > 0`, send a multicast FCM notification to all the user's tokens via `admin.messaging().sendEachForMulticast(...)`.
   e. Notification payload: `title: "Your queue is ready"`, `body: totalDue === 1 ? "1 person is waiting in your queue." : \`${totalDue} people are in your queue today.\``
   f. Clean up any invalid/expired tokens returned in the multicast response (remove them from the user doc using `arrayRemove`).

   Install the required dependency in `functions/`:
   ```
   cd functions && npm install firebase-admin firebase-functions
   ```
   (These are likely already present — check `functions/package.json` first.)

**Environment variable:**
- The VAPID key goes in `.env.local` as `VITE_FCM_VAPID_KEY=...`. Add the key name (not the value) to `.env.example` if one exists, or document it in a comment in `notifications.js`.

### What NOT to do
- Do not add any UI beyond the silent permission request. No modal, no banner, no settings toggle — that's a future iteration.
- Do not hard-code the Firebase config values anywhere new; reference the existing `src/firebase/config.js`.

## TASK 2 — Profile Notes (Phase 3.2)

Add a persistent, freeform `notes` field to each profile. It auto-saves as the user types.

### What to build

**Firestore / db.js:**

1. In `src/firebase/db.js`, add a new function:
   ```js
   export function updateProfileNotes(profileId, notes) {
     return updateDoc(doc(db, 'profiles', profileId), { notes: notes ?? '' });
   }
   ```
   This is a dedicated single-field update — do not reuse `updateProfile` for this, because `updateProfile` runs through `normalizeProfilePatch` which shouldn't touch `notes`.

**DataContext:**

2. In `src/context/DataContext.jsx`, add `updateProfileNotes: dbApi.updateProfileNotes` to the `actions` useMemo object.

**ProfileDetail.jsx (presentational):**

3. Add a `notes` prop and an `onNotesChange` prop to `ProfileDetail`.

4. Add a "Notes" section to `ProfileDetail.jsx`, positioned **between** the cadence pills and the Active Requests section (so it appears near the top, below identity, before the prayer list). The section should look like:

   ```
   ── NOTES ──────────────────────────────
   [ a soft textarea, auto-resizing,
     placeholder: "Add notes about this person…"
     saves on blur + 500ms debounce ]
   ```

   Style guidelines (match the existing palette):
   - Section label: same `text-[10px] font-semibold uppercase tracking-[1.8px] text-[#9A958A]` class as "ACTIVE REQUESTS"
   - Textarea: `w-full rounded-[20px] border border-[#EBE6DC] bg-white px-[15px] py-[13px] font-['Newsreader'] text-[15px] text-[#26241F] placeholder:text-[#B0AB9E] focus:border-[#D8B98E] focus:outline-none resize-none`
   - Minimum height: `min-h-[80px]`
   - Auto-grow: use an `onInput` handler that sets `e.target.style.height = 'auto'` then `e.target.style.height = e.target.scrollHeight + 'px'`
   - A small "Saved" indicator (a simple `text-[11px] text-[#9A958A] italic` label) that appears briefly after a save completes. Use a `useState` + `setTimeout(300ms)` to flash it.

   Do NOT add a save button. It should feel ambient and automatic.

**ProfilePage.jsx (smart page):**

5. Pass `notes={profile.notes ?? ''}` down to `<ProfileDetail>`.

6. Implement the `handleNotesChange` callback in `ProfilePage.jsx`. Use `useCallback` with a `useRef`-based debounce timer (500ms). On each call, clear the existing timer and set a new one that calls `updateProfileNotes(profile.id, newNotes)`. This keeps the write calls coalesced even for fast typists.

   ```js
   const notesTimerRef = useRef(null);
   const handleNotesChange = useCallback((newNotes) => {
     clearTimeout(notesTimerRef.current);
     notesTimerRef.current = setTimeout(() => {
       updateProfileNotes(profile.id, newNotes);
     }, 500);
   }, [profile?.id, updateProfileNotes]);
   ```

   Pass this as `onNotesChange={handleNotesChange}` to `<ProfileDetail>`.

### What NOT to do
- Do not add `notes` to the `addProfile` or `CardForms` flows — it should only be editable from the profile detail page, not from the quick-add form.
- Do not use a subcollection for notes. It's a single string field directly on the profile document.
- Do not debounce inside `ProfileDetail.jsx` — keep debounce logic in the smart page (`ProfilePage.jsx`).
